# 微信回复助手产品需求文档

版本：v1.0（开发前设计基线）
日期：2026-11-16
状态：MVP 需求基线；已落地 v0.1 桌面体验版子集，实际范围及验证见 [DEV_STATUS.md](DEV_STATUS.md)。本文默认值和验收目标不代表已经全部实现或通过。

## 1. 产品目标

面向在 Mac 上使用个人微信的用户，通过快捷键唤起轻量浮窗，结合指定会话的近期聊天、用户希望表达的内容和对方的沟通档案，给出可编辑的回复候选。用户决定是否采用，并自行在微信发送。

首版聚焦单人、单台 Mac、单个微信账号。后续评审已追加群聊回复模式：明确选择消息和回复对象，不创建群或群成员画像。当前体验版包含私聊与群聊示例，真实微信读取仍待接入。客户、同事、朋友等关系由用户补充，不按会话名称猜测。

本轮界面调整：语气模板统一在设置中新增、编辑、删除和开关，仅开启的模板显示在聊天面板；本次背景默认关闭，打开才显示输入框，关闭不发送该字段。聊天记录改为独立视图，含手动刷新与可配置的自动同步（默认关闭、30 秒，可设 5～300 秒）。当前刷新明确标为示例，自动同步不调用模型、不生成画像、不清除草稿，窗口隐藏、生成中或手动片段时暂停。

核心使用闭环：唤起浮窗 → 确认回复对象 → 读取近期消息 → 选择任务和语气 → 可选补充背景 → 生成 3 条候选 → 编辑 → 复制。

## 2. 已有证据与产品边界

| 项目 | 2026-11-16 状态 | 对产品的约束 |
| --- | --- | --- |
| 指定会话数据库读取 | 本机样本通过；最近 10 条读取成功，5 条历史文字的内容、顺序、收发方一致 | 采用数据库只读路线，仍需封装和持续验证 |
| 查询耗时 | 单次查询及归属整理约 1.5 秒 | 不是平均值、P95 或性能承诺 |
| 当前已打开会话识别 | 未验证成功 | MVP 必须显式选择会话，不宣称自动跟随微信 |
| 新消息实时性 | 未验证 | MVP 在唤起、选会话、手动刷新时读取；后台监控不进入首版 |
| 图片、视频 | 仅类型占位验证 | 不把占位符当作已理解的内容 |
| 模型 API、桌面端 | 已有体验版工程和模型调用代码；真实模型未联调 | 演示候选不作为 AI 运行证据 |
| AX、旁白、OCR | 本机原路线未获得可用聊天正文；用户不接受其作为主方案 | 不作为 MVP 依赖；不恢复旁白；OCR 仅为未来可选辅助 |

完整证据见 [公开验证边界](VALIDATION.md)。数据库读取依赖本机已有数据与可用凭据，不能承诺微信升级后持续兼容，也不承诺“零风控”。

## 4. 页面与交互

### 4.1 快捷浮窗

- 默认快捷键建议为 `Option + Space`，可以修改；注册冲突时给出提示。
- 主浮窗建议宽 380～420 px，支持拖动、置顶和关闭到托盘。全屏应用、多屏幕、不同桌面的行为需实机验收。
- 顶部显示明确的回复对象选择器和“关于 TA”入口。首次不默认替用户选人；之后可恢复上次对象，但必须显示姓名并重新读取。
- 展示“最近读取时间”“上下文来源”“条数”“是否有缺失/截断”，可以展开查看消息及收发方向。
- 提供任务、语气、本次背景、参考档案开关、候选及编辑区。
- 不自动粘贴到微信，不模拟发送快捷键，不修改微信输入框。

### 4.2 关于 TA

入口位于联系人旁。打开后在浮窗侧面展开档案；窄窗口可改为单独视图，避免主界面越堆越宽。包含三个页签：

1. **资料**：已确认的长期资料及近期事项；可新增、编辑、锁定、删除和查看来源。
2. **AI 观察**：有聊天依据但需要用户判断的沟通习惯；默认不进入回复上下文。
3. **更新记录**：资料变化、自动加入的事实、用户处理结果和待核对冲突。

档案分为：关系与称呼、沟通习惯、明确偏好、相处边界、近期重要事项。每类可以有多条信息。没有资料时显示空状态，不编造完整画像。

### 4.3 本次背景与长期档案

| 内容 | 例子 | 保存和使用规则 |
| --- | --- | --- |
| 本次补充背景 | “想答应，但希望晚半小时” | 仅用于当前联系人当前编辑会话；切换联系人、关闭浮窗后清除；不自动进入档案 |
| 用户手动补充 | “工作日午休不方便接电话” | 加入该联系人的档案，默认锁定，可编辑 |
| 聊天中明确表达 | “之后给我 PDF 就行” | 自动更新已开启时，可加入有来源的事实记录 |
| AI 观察 | “约时间时经常主动给出地点” | 保留具体依据，等待用户确认；不形成绝对性格结论 |
| 近期事项 | “这周在准备汇报” | 有生效/到期时间；AI 无法确定期限时先待确认，不作为永久偏好 |

## 5. MVP 功能列表

| 编号 | 功能 | MVP 行为 |
| --- | --- | --- |
| F-01 | 桌面入口 | 快捷键、托盘、显示/隐藏、置顶、恢复窗口位置 |
| F-02 | 会话选择 | 搜索/选择已读取到的私聊，保存稳定 ID；同名必须区分；账号不明确时停止读取 |
| F-03 | 聊天上下文 | 默认取最近 50 条，界面最大 200 条；显示时间及方向；读取失败支持显式切换到手动粘贴 |
| F-04 | 任务和语气 | 回复对方、改写我的上一句、主动跟进；四种预设语气及自定义语气 |
| F-05 | 本次背景 | 多行输入；不会自动长期保存；可以不填 |
| F-06 | 候选回复 | 每次 3 条；可选择、编辑、复制；加载、取消、超时和重试状态明确 |
| F-07 | 手动沟通档案 | 五类资料增删改、默认锁定、来源区分、近期项有效期、本次参考开关 |
| F-08 | AI 档案分析 | 从选定会话的文字生成有证据的事实/观察；支持“从近期聊天更新”和联系人级自动更新开关 |
| F-09 | 更新核对 | 明确事实可自动加入；观察待确认；与任何手动资料/锁定资料冲突时待核对；保留旧资料、采纳替换、加入近期偏好 |
| F-10 | 清理与排除 | 删除资料及其正文历史、来源摘录；可指定“以后不再记录此项”；恢复记录需主动解除排除 |
| F-11 | 配置和隐私 | 配置模型地址/模型名/API Key，测试连通；首次外发前确认处理范围；显示读取诊断；清空联系人的本地资料 |

### 5.1 上下文与回复规则

- 数据库来源优先使用上游的本人标记，不能靠气泡位置、昵称或措辞猜测。本人身份不明时禁止自动生成“回复对方”，要求用户在手动输入中明确标注。
- 最后一条为己方消息时，默认提示“最后一句是你发的”。用户可选择改写或主动跟进，不冒充对方刚发了新消息。
- 手动输入必须区分“我/对方”；界面始终注明这是手动片段，不能代表实时未读状态。
- 明确的本次表达目的和自定义语气优先于默认表达偏好；已知事实与相处边界仍用于提醒，不为了满足语气而编造事实或承诺。
- 只使用该账号该联系人的已生效资料。关闭“本次参考沟通档案”后，本次模型请求完全不带档案；该开关不等于关闭档案自动更新，两者独立并有清楚标签。
- 图片、视频、语音、文件、撤回或未知消息只能显示准确的类型占位。MVP 不读取附件内容，不将其送入模型做理解。
- 模型输入默认最多最近 50 条文字、单条最多 2,000 字符、总聊天正文最多 20,000 字符；超限保留较新的内容，并明确展示截断提示。提供的是选定片段，不宣称完整历史。
- 切换联系人时取消旧请求、清除本次背景和草稿；旧结果不得显示到新联系人的面板。

### 5.2 档案自动更新规则

1. 每个联系人默认关闭。用户开启并确认模型处理范围后，首次分析当前选定的最多 50 条文字。
2. 后续只在该会话成功读取后检查新增消息；有至少 10 条新增消息，或有新增消息且距上次成功分析满 5 分钟时触发。用户也可主动更新。
3. MVP 不在浮窗隐藏时扫描全部会话，不分析未选择的联系人；没有新消息不重复调用模型。
4. 模型给出建议，本地程序验证账号、会话、发送者、消息 ID、引用文本和排除规则，再决定是否写入。真实引用不代表 AI 的解释一定正确。
5. “聊天事实”限对方明确表达、引用可核对的信息；观察、期限不明、隐含偏好以及冲突进入待确认。
6. 不静默覆盖用户手动补充，即使用户解除锁定仍保留手动来源优先级；自动加入的未锁定事实可以在证据充分、无冲突时更新，并记录历史。
7. 自动分析失败不影响回复生成，不推进成功分析游标；重试不能重复加入同一建议。历史读取不完整时显示分析范围，不能标注“已分析全部”。

## 6. 非功能需求

以下为开发验收目标，尚未测得。基准先采用当前 Apple silicon Mac；完整硬件与数据量须记入测试报告。

| 类别 | 需求/目标 | 测量方式 |
| --- | --- | --- |
| 平台 | 首发 Apple silicon、macOS 14+；实际当前仅 macOS 26.6.2、微信 4.1.13 有读取样本 | 先验收当前机器，其他版本标为未验证 |
| 交互 | 已启动应用唤起浮窗 P95 ≤ 300 ms | 连续 30 次热唤起，单独统计首启 |
| 查询 | 已配置数据源读取最近 50 条 P95 ≤ 3 s | 同一指定会话 30 次查询，记录冷/热差异、缺失标记 |
| 模型 | 目标 90% 请求 15 s 内完成，单次 45 s 超时，可取消 | 选定模型和网络后测试 20 组脱敏或虚构场景；外部服务影响需单列 |
| 资源 | 隐藏窗口时不轮询微信、不调用模型；窗口操作不被数据库和网络任务阻塞 | 观察空闲 10 分钟及生成期间窗口操作 |
| 安全 | 微信源库只读；模型 Key 放 Keychain；微信凭据沿用受限文件，不进入前端、日志或项目文档 | 测试替身检查调用参数、权限与日志 |
| 数据 | 不默认保存完整聊天、生成正文、本次背景；仅存必要档案与来源摘录 | 检查应用库、日志和导出内容 |
| 网络 | 本地读取与本地资料编辑不联网；首次向配置的模型外发前说明并确认 | 断网测试；确认前不发起含正文请求 |
| 可用性 | 键盘可完成选择候选与复制；支持深浅色、长文本和 320 px 窄视图 | 前端交互检查和原生窗口人工验证 |
| 可维护性 | 数据源、模型、档案规则、UI 解耦；依赖固定版本；保留样本契约测试 | 代码审查、锁文件和测试报告 |

本地 SQLite 档案库在 MVP 不做数据库级加密，使用用户目录权限保护；“本地存储”不等于加密。API Key 与微信数据库密钥不存入该库。数据库级加密可在后续迭代评估。

## 7. 验收标准

| 编号 | 条件与操作 | 通过标准 |
| --- | --- | --- |
| AC-01 | 应用运行时按快捷键，再次按下 | 正确显示/隐藏；冲突可修改；不误触微信输入框 |
| AC-02 | 搜索两个同名联系人 | 展示可区分的标识；未明确选择前不读取任何一个 |
| AC-03 | 读取已配置的私聊样本 | 消息内容、方向、顺序可与微信样本逐条核对；有缺失则可见，不能伪报完整 |
| AC-04 | 最后一条是我发的 | 默认提示等待；只有显式改写/跟进才继续相应任务 |
| AC-05 | 改变语气、填写背景后请求真实模型 | 返回 3 条可编辑文字；背景中的事实未被改写成未经确认的承诺；真实模型测试有单独证据 |
| AC-06 | 选择并编辑候选后复制 | 剪贴板与编辑后文字一致；微信没有自动收到消息 |
| AC-07 | 在 A 联系人添加锁定资料，再切到 B 并重启应用 | A 资料保留，B 看不到；本次背景与草稿不跟随、不长期恢复 |
| AC-08 | 输入带可核对引文的 AI 事实、观察、冲突三类结果 | 事实按规则入库；观察和冲突待确认；每条有来源；无引文/跨会话引用拒绝写入 |
| AC-09 | 新信息与手动资料不同 | 原资料不变；用户可保留、替换或加入近期项；操作记录与最终资料一致 |
| AC-10 | 关闭本次参考档案，检查模型请求 | 无档案正文或档案证据；自动更新开关不被悄悄改动 |
| AC-11 | 删除并选择不再记录某项，重新分析相同消息 | 该项及相关正文历史/摘录不再展示；不会自动重新加入；其他偏好仍可记录 |
| AC-12 | 凭据失效、上游部分解码失败、模型超时/返回非法格式 | 分别显示准确原因；可取消/重试/手动输入；不显示虚构成功、不覆盖旧资料 |
| AC-13 | 生成期间切换联系人 | 旧任务取消或其结果被丢弃；不串联系人；新联系人编辑区为空 |
| AC-14 | 未确认云端处理范围时开启分析或生成 | 先显示服务商与发送范围；拒绝后不发送正文；更换端点后重新确认 |
| AC-15 | 检查应用存储与日志 | 无 API Key、微信密钥、完整聊天和原始模型响应；允许的档案摘录范围有说明 |

## 8. 后续迭代与不做事项

### MVP 后迭代

- P1：可见浮窗内的可控自动刷新、更多历史片段、近期项到期提醒、语气模板、档案导入导出、已确认回复历史（用户主动开启）。
- P2：用户自己的表达风格学习、本地模型适配、可选 OCR/分享导入辅助、可选 MCP 只读接口。
- P2：如果取得可重复的当前会话识别证据，再提供“跟随微信当前会话”；未识别时保留显式选择。

### 当前不做

自动发送、批量联系客户、群聊成员画像、朋友圈、企业微信、Windows/iOS、云端同步、全量历史复制和无限后台分析。不因读取失败而自动改签微信、关闭 SIP、降级微信或恢复旁白。新的凭据采集操作与日常查询分离，不属于一般功能测试。

## 9. 尚待开发时确认

1. 实际使用的模型服务商、模型名及费用预算；框架先支持一个可配置适配器，不默认绑定某个服务商。
2. GreenBubbles 固定版本的完整 JSON 契约、新消息可见延迟和打包后访问能力。
3. 正式应用名称、Bundle ID、签名证书、分发方式及 macOS 最低版本的实机覆盖。

这些事项不阻止编写设计文档；其中数据契约、凭据访问和真实模型连通必须在 MVP 实现前段解决。
