# 微信回复助手开发计划

版本：v1.0；日期：2026-11-16。按“先验证关键路径，再完成 MVP，再扩展功能”执行。本文任务没有因为写入文档而视为已完成。

## 1. 当前基线

当前已建立 v0.1.0 Vue/Tauri 工程、SQLite 档案、设置和本机体验包，使用虚构数据评审页面，详见 [DEV_STATUS.md](DEV_STATUS.md)。历史只读样本验证尚未产品化，原始报告不公开。

M1/M3/M4 仅完成体验版子集；真实读取契约、增量同步、真实模型联调和 M5 自动提取仍待完成。完整 MVP 的验收要求保持有效。

参考：[PRD](PRD.md)、[架构](ARCHITECTURE.md)、[数据库](DB_DESIGN.md)、[项目规则](../AGENTS.md)、[公开验证边界](VALIDATION.md)。

## 2. MVP 范围

后续用户评审已授权并完成体验版增量：群聊消息选择与回复对象、无画像群聊模式、设置页语气模板及启用开关、默认折叠的本次背景、独立聊天记录与示例刷新、可配置间隔的自动刷新（保留草稿）、应用级 HTTP 客户端复用。真实微信新消息同步、真实模型联调和内存稳定性测试继续保持未完成，不因这些页面交互通过而勾选完成。

MVP 必须走通：快捷唤起 → 显式选择私聊 → 读取上下文 → 选任务/语气/背景 → 真实模型生成 → 编辑复制；同时包含手动沟通档案、带来源的 AI 更新、观察/冲突核对和资料清理。

群聊示例已纳入体验版；真实群聊读取在只读会话契约明确后接入。不把自动发送、自动跟随当前微信会话、隐藏时后台扫描、附件理解或 MCP 接入夹进 MVP。

## 3. M0：开发前关键验证

| 任务 | 产出 | 完成标准 |
| --- | --- | --- |
| M0-01 固定读取依赖 | 版本、上游提交/发布来源、SHA-256、LICENSE/NOTICE 清单 | 本机当前可用程序与记录一致；不自动升级 |
| M0-02 固定数据契约 | 脱敏/虚构会话和消息 JSON 样本、字段映射说明 | 区分默认 JSONL 和完整 JSON；确认 message ID、本人标记、时间、分页、缺失标记 |
| M0-03 确认账号绑定 | 明确账号稳定标识、query profile 与 source root 的绑定方案 | 不依赖“最近使用的目录”；不覆盖已有用户 profile；同名不误读 |
| M0-04 验证新增消息与分页 | 实机样本报告、重复读取和增量去重方案 | 由用户正常聊天产生新消息，记录出现延迟及方向；本工具不发送测试消息；分页不漏边界 |
| M0-05 排查读取副作用 | 文件写入/媒体缓存行为说明 | 只取文字与类型占位；不产生非必要附件物化；无法禁止时明确最小适配改动再实现 |
| M0-06 选定一个模型并连通 | 无聊天的请求/响应契约与配置需求 | 先测试固定虚构文本；确认认证、输出解析、超时、费用记录方式，不要求用户把 Key 发到聊天 |
| M0-07 复核实现基线 | 五份文档修订、未解决项清单 | 将 M0 的实际限制回填文档；失败项目保持未完成，不用临时手动输入冒充自动读取 |

M0-04 验证到库延迟是评估，不构成 MVP 承诺自动实时刷新；真实模型质量在 M3 再验收。只有稳定读取和最小模型协议通过后，才进入完整功能开发。

## 4. M1：工程骨架与原生能力

依赖：M0 关键契约明确，用户已要求开始正式实现。

| 任务 | 产出 | 完成标准 |
| --- | --- | --- |
| M1-01 创建工程 | npm workspace、Vue/TS/Vite、Tauri 2、固定工具链与锁文件 | 目录按架构分层；不覆盖原 Python 和验证资料；Git 初始化/提交另按用户指令 |
| M1-02 最小窗口 | 主浮窗、托盘、显示隐藏、置顶、位置保存 | 当前 Mac 原生运行验证；快捷键冲突能修改；不操作微信输入框 |
| M1-03 命令桥与错误 | DTO、bridge、标准错误、事件监听和取消 | 前端不直接操作 shell/SQL/Keychain；加载与失败状态可见 |
| M1-04 SQLite 基础 | 迁移、仓储、权限及清理入口 | 临时库初始化、外键和唯一约束测试通过 |
| M1-05 配置与 Keychain | 模型配置页、Keychain 保存/删除、处理范围确认 | UI 只能看到 Key 已设置；端点变化使确认失效；日志不含秘密 |

阶段演示：浮窗可唤起，设置可保存，无微信与模型真实正文读取。

## 5. M2：只读聊天上下文

依赖：M1 命令桥、M0 查询契约。

| 任务 | 产出 | 完成标准 |
| --- | --- | --- |
| M2-01 ChatSource 适配 | 固定子进程、命令白名单、超时/取消、错误分类 | 无 shell 拼接；无采集/发送/改签命令；契约样本测试通过 |
| M2-02 账号及会话 | 显式绑定、私聊列表/搜索、重名区分 | 使用稳定 ID；身份和账号不明确时停止 |
| M2-03 上下文快照 | 最近 50 条、最大 200 条、方向/时间/类型、来源与缺失提示 | 实机样本核对；部分结果不冒充完整；附件只占位 |
| M2-04 手动上下文 | 我/对方标注、解析错误提示、手动来源标记 | 数据库失败后显式切换，不自动伪装；不触发档案自动学习 |
| M2-05 任务判断 | 己方最后发言拦截、改写/主动跟进分支 | 不回复自己；三类任务测试可区分 |

阶段演示：选定对象能看到准确近期片段；不使用 AX、旁白或 OCR。

## 6. M3：真实回复生成闭环

依赖：M2 快照与 M1 配置。

| 任务 | 产出 | 完成标准 |
| --- | --- | --- |
| M3-01 提示词与模型适配 | 最小输入预算、任务/语气/背景、结构化输出 | 原文作为数据；3 条候选；非法响应/空响应不报成功 |
| M3-02 浮窗回复界面 | 对象、上下文展开、语气、自定义、本次背景、候选和草稿 | 按模块拆分；窄视图/深浅色/键盘操作可用 |
| M3-03 取消与会话切换 | requestId、终态事件、取消旧请求 | 切换对象清空背景/草稿，旧结果不能串到新对象 |
| M3-04 编辑与复制 | 编辑区、原生剪贴板、复制反馈 | 剪贴板是编辑后的文字；不自动粘贴/发送；不伪报已发送 |
| M3-05 质量与性能评估 | 20 组虚构/脱敏场景，延迟和错误记录 | 覆盖四种语气、三类任务、背景约束；有真实调用证据，不用原型固定文案代替 |

阶段演示：不带长期档案也能完成一次真实回复生成与复制。

## 7. M4：手动沟通档案

依赖：M1 存储、M2 身份映射。可在 M3 后推进，不先增加自动分析复杂度。

| 任务 | 产出 | 完成标准 |
| --- | --- | --- |
| M4-01 资料管理 | 五类资料、具体主题、增删改、锁定、生效/到期时间 | 人工项默认锁定，近期项有期限；资料与联系人严格绑定 |
| M4-02 关于 TA | 资料/AI 观察/更新记录三页签，空态和来源入口 | 页签、编辑、来源展开可用；无资料不编造画像 |
| M4-03 回复融合 | 本次参考开关、有效资料装配、参考摘要 | 关闭后请求不含档案；只读有效资料；本次背景不进入长期库 |
| M4-04 删除与排除 | 关联正文清理、具体事项排除、解除入口、联系人清空 | 主表/提议/证据/历史一致清理；排除项不被改写绕过 |

阶段演示：同一联系人重启后能继续用手动资料；其他联系人看不到；本次背景不恢复。

## 8. M5：AI 档案更新与核对

依赖：M4 资料规则、M0 增量契约、M3 模型适配。

| 任务 | 产出 | 完成标准 |
| --- | --- | --- |
| M5-01 提取与证据 | 事实/观察/冲突 DTO、message ID 与引文校验 | 无依据、错方向、跨会话证据不能入库 |
| M5-02 合并规则 | 人工优先、锁定、主题去重、近期项与排除 | 任意手动差异先核对；自动事实更新留历史；过期项不参与生成 |
| M5-03 核对交互 | 保留、采纳替换、加入近期偏好、确认观察/忽略 | 用户决定与资料、证据、历史一致；近期采纳确认期限 |
| M5-04 自动触发 | 联系人默认关闭、首次分析、10 条/5 分钟阈值 | 仅成功读取选定会话后触发；隐藏不扫描；无新消息不付费调用 |
| M5-05 检查点与版本 | 连续处理边界、重试去重、profile_revision | 失败不推进成功边界；人工修改后重新核对，不覆盖旧快照 |
| M5-06 分析隔离 | 后台任务状态、失败重试、单联系人单任务 | 分析失败不阻塞回复；手动片段不自动形成长期画像 |

阶段演示：一组虚构证据先证明全部规则，再经用户选定会话做最少真实验证；不输出或提交客户原文。

## 9. M6：MVP 验收与个人测试包

| 任务 | 产出 | 完成标准 |
| --- | --- | --- |
| M6-01 完成验收矩阵 | PRD AC-01～AC-15 对照报告 | 每项写明自动测试/实机/未通过；无遗漏能力冒充完成 |
| M6-02 异常与清理 | 凭据失效、格式变化、部分消息、超时、清理流程 | 错误准确；无秘密/原文日志；不自动修改微信环境 |
| M6-03 目标性能 | 30 次浮窗、30 次查询、20 组模型调用及空闲观察 | 对照 PRD 目标；不达标时写出真实结果和影响 |
| M6-04 打包 | arm64 查询 sidecar、LICENSE/NOTICE、个人测试包 | 打包后的 app 能完成实际读取/Keychain/模型/复制，不能只验证 dev 模式 |
| M6-05 同步文档 | 实际目录、版本、命令、支持矩阵、使用/故障说明 | AGENTS 的命令从“约定”更新成实测结果；保留不兼容和未测环境 |

MVP 完成定义：上述主闭环和沟通档案规则通过，真实 macOS 应用已验证，剩余限制清楚；没有“可以运行前端，所以桌面工具完成了”的替代说法。

## 10. MVP 后迭代

### P1：提高日常效率

| 任务 | 前置条件 | 验收重点 |
| --- | --- | --- |
| 浮窗可见时自动刷新 | M0 新消息延迟及查询成本已测量 | 默认最短 5 秒，隐藏即停止；显示读取时间，不承诺未验证的实时性 |
| 更多历史与按需摘要 | 已有分页和缺失标记 | 摘要带范围与来源；不默认导出全量库 |
| 语气模板 | MVP 质量评估通过 | 自定义保存、联系人默认语气和本次覆盖 |
| 近期项提醒/管理 | 已有有效期与资料查询 | 到期后不参与生成，可续期或归档 |
| 档案导入导出 | 已有清理和来源规则 | 用户主动操作；明确包含哪些正文；导入不串账号 |
| 可选回复历史 | 用户主动开启保存 | 明确只记录候选/复制状态，不虚构发送回执 |
| 本地兼容模型 | 实际服务协议验证 | 单独配置 loopback HTTP 与处理范围，不改变云端默认规则 |

### P2：扩展能力

- 用户自己的表达风格学习：先获取明确启用与最小样本，独立于“对方档案”。
- 当前微信会话跟随：先做不依赖主 OCR 的识别实验，有稳定证据才加入正式流程。
- 可选 OCR/分享导入：仅补充无法读取的片段，标记来源，不代替主数据通道。
- 可选 MCP：复用应用服务提供只读上下文与草稿，不暴露发送或任意查询。
- 数据库级加密、原生自动化测试、Intel/其他平台：分别评估成本和依赖，不因 Tauri 跨平台便自动承诺支持。

## 11. 执行与记录规则

- 以 M0～M6 顺序建立任务，完成一段给出可演示结果与验证记录；本计划不预报未经估算的日历工期。
- 每项实现前确认目标文件、现有改动和影响；不顺手重构历史验证代码。
- 只给有业务风险和决策价值的规则写测试，不为静态样式或实现镜像堆断言。
- 使用虚构数据做自动测试；真实读取只限用户指定账号/会话，不发送消息，不保存客户原文到仓库。
- 如要增加改签、管理员操作、数据库写入等与现有方案不同的步骤，先单独说明其必要性和影响；本计划没有授权这些操作。
